Сотрудники перестают ходить с одними и теми же вопросами к бухгалтерии и IT:
бот отвечает по внутренней базе документов — **только по ней**, и всегда
показывает, из какого документа взят ответ.

## Бизнес-проблема

HR и IT-поддержка тонут в повторяющихся вопросах («сколько дней отпуска»,
«как сбросить пароль»). Облачные AI-чаты на рабочих данных использовать нельзя,
а обычный поиск по wiki не отвечает на вопрос — его приходится собирать руками.

## Что сделано и результат

- Загружаешь `.md`-документы в папку → бот ищет по смыслу (TF-IDF, офлайн),
  расширяет запрос синонимами, отдаёт ответ **с цитатой и документом-источником**.
- Нет ответа в базе — бот честно говорит «в базе нет ответа», не выдумывает.
- Метрика качества внутри: golden-набор «вопрос → документ», hit-rate@3,
  офлайн A/B двух стратегий поиска — `/api/eval`.
- Работает без интернета и без API-ключей: вставил документы — получил бота.

Результат для бизнеса: 1 файл с инструкцией вместо 20 однотипных вопросов
в день; ответ всегда со ссылкой на регламент.

## Демо за 2 минуты

```bash
pip install -r requirements.txt
uvicorn app:app --port 8095        # или: python demo.py — 3 готовых вопроса-ответа
```

```bash
curl -X POST localhost:8095/api/ask -H "Content-Type: application/json" \
  -d "{\"q\": \"сколько дней отпуск\"}"
# → {"answer": "Отпуск: основной оплачиваемый отпуск — 28 календарных дней...",
#    "sources": [{"doc": "hr_policy", "score": 0.87}], "mode": "offline"}
```

Своя база: положи `.md` в `data/docs/` (чанки по заголовкам `## `) — индекс
строится при старте автоматически. Секретов нет — `.env` не нужен.

## Стек и архитектура

Python 3.11 · FastAPI · собственный TF-IDF (без sklearn/numpy) · pytest · GitHub Actions CI

```
docs/*.md → чанки по "## " → TF-IDF индекс
вопрос → синонимы → топ-3 чанка → ответ + sources[{doc, score}]
score=0 → честный отказ («в базе нет ответа»)
```

Путь апгрейда: поиск на embeddings/Ollama — заменяется один модуль,
API и тесты не меняются.
